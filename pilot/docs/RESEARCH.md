# 从教学试点到独立研究：可行性与边界

## 当前成果的定位

这是一套已运行的小型形式化与 Agent 工程试点，包含简洁的数学种子、错误命题、语义约束和跨语言验证。两个数学结论本身不是新结果；有限稳定子证明也没有建立新的自检验定理。当前 7 个 Agent 任务的回放验证只说明工程链条工作，**不能支持模型成功率、自动发现证明或超越已有方法的论断**。

仅以“调用模型→Lean报错→再调用模型”为贡献，独立研究价值有限。LeanDojo、ProofNet 等已经建立了证明交互、检索、自动形式化和评测的研究基础。近期工作进一步强调形式化陈述与原题不一致的问题。因此，选题要转向可证伪的具体研究问题，而不能把一个串联接口包装成新算法。

## 优先方向：科学命题的语义保真与反例反馈

建议研究问题：在相同模型、相同预算下，加入可执行的有限模型反例与目标契约检查，能否减少“编译通过但语义错误”的输出，并改善跨问题族迁移？

其潜在贡献有三部分：

- **任务与错误结构**：每道题提供自然语言、参考 Lean 陈述、独立可执行语义、正确性/否定证据、可控变异。重点覆盖量词、域、位序、运算、归一化、假设加强及作用顺序。
- **反馈方法**：将 Lean 类型错误、具体数学反例和语义偏离分别反馈；记录模型修复了哪一层，是否引入新的错误。反例存在时转为否定/修正候选命题任务，不能要求模型强行证明错误结论。
- **迁移评价**：把量子问题作为一类数据，另加入布尔代数与可逆逻辑、有限置换/群作用、有限组合恒等式等至少两个非量子问题族。比较训练/开发时未见的问题结构。

本试点的严格陈述固定只能阻止证明阶段偷换目标；它不能自动解决自由 autoformalization 的语义对齐。研究阶段需要人工金标准、双向蕴含或能鉴别关键语义的辅助性质，并对自动语义指标的误判率作独立评测。

## 最小可发表研究规模（建议，不是已完成数据）

第一轮先做 30—50 个经过人工核验的开发任务，验证错误类型是否足够丰富。若有信号，再扩展到约 200—300 个基础命题及其变异；基础命题而不是变异样本作为独立统计单位。

按数学结构/生成模板分 train/dev/test，同一公式的变量改名、参数改变、同一反例的近似版本不得跨划分。公开本试点只作开发集。隐藏测试在调试结束前冻结；时间切分并不能保证大模型没有预训练污染，应记录公开时间与来源并说明不可排除的污染。

建议至少两个不同模型、三个重复运行种子或重复采样；温度为零也不保证服务端完全可复现。预算先固定每题最多 3 次模型调用、统一输出 token 上限与 Lean 超时；另报告实际 token、工具调用和价格日期。单纯等次数并不等于等费用，成本对比需有按 token 或金额匹配的补充分析。

## 对照与消融

| 方法 | 检验的问题 |
|---|---|
| 固定 tactic/检索模板，不调用模型 | 简单穷举能否已解决所有种子任务 |
| 模型一次输出，无反馈 | 单次基础能力 |
| 模型＋Lean 错误反馈 | 类型和证明修复的增益 |
| 模型＋Lean＋独立反例反馈 | 具体数学反馈的增益 |
| 模型＋Lean＋反例＋语义检查 | 编译成功是否仍掩盖陈述漂移 |

所有方法使用相同可见定义和辅助引理；不能让某一方法看到目标证明。必须包含成立但反直觉的变异，例如本试点的 D/X 交换，以检验方法是否过度拒绝。自由证明体评测与受限词汇评测应分开，门禁拒绝单列，不伪装成模型失败。

## 核心指标

| 指标 | 定义与注意事项 |
|---|---|
| 严格端到端正确率 | 自然语言语义正确且 Lean 编译/审计通过的比例 |
| 形式化语义偏离率 | 类型正确但与原意不等价的比例，人工复核/双向蕴含作依据 |
| 负例误接纳率 | 错误或目标被修改的命题被系统标为成功的比例 |
| 有效修复率 | 初次失败且有后续预算的题中，最终严格成功的比例 |
| 修复引入错误率 | 修复类型错误后反而改变语义的比例 |
| 正确命题误拒绝 | 与未完成/超时分开；仅有证明失败不能判定数学错误 |
| 成本 | 每个严格成功题的模型 token、金额、Lean 调用、墙钟时间 |
| 迁移差距 | 未见问题族与开发问题族的严格正确率差 |

报告每题配对结果、95% 置信区间（以基础命题/模板为簇 bootstrap）和误差案例；不能把一个模板的几十个变异当几十个独立发现。没有效果或成本更高也应报告。

## 何时继续，何时止步

继续的条件：反例/语义反馈在至少两个问题族、两个模型上稳定改善严格正确率或降低误接纳，并且改善不能被纯 tactic 搜索、更多 token 或泄漏答案解释。

若扩展后仍是三变量枚举题，或者方法仅比不合理的弱基线好，适合形成教学资源、工具演示或学生科研训练报告，不宜包装为强研究论文。若方法和跨域评测均扎实，可先考虑 AI4Math/形式化方法相关 workshop 或工具/教育类成果，再依据实际贡献选择更高层级 venue；现阶段不能保证录用层次。

另一条方向是“跨语言科学计算的变异驱动验证”：自动生成 Boolean-phase、可逆逻辑和有限线性变换的可验证规格，再系统植入位序/相位/归一化错误，研究不同验证组合的检出与漏检结构。这更贴近软件测试与形式化验证，需要扩展到真实的独立实现和有意义的缺陷，而非仅统计自己植入的明显错误。
